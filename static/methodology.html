Risk Assessment Methodology

Every score and label DOJAA emits is grounded in a public, peer-reviewed framework. This page documents which standards are used, how they are combined, and how to reproduce any number on the dashboard from the raw data sources.

2. Per-finding scoring

Each entry in the finding catalog (dojaa/scoring/findings.py) carries a representative CVSS v3.1 Base vector chosen to model the typical real-world manifestation of the weakness. The Base score is computed from the vector using the formulas in FIRST.org §7.1 — the implementation in dojaa/scoring/cvss.py is verified against the FIRST online calculator (see the unit tests).

CVEs matched to a host carry their own CVSS metrics straight from NVD; DOJAA does not re-score CVEs.

3. Finding categories

Every finding is one of four categories. The category decides whether the finding's CVSS contributes to the host's headline severity. This mirrors how Tenable, Qualys and Rapid7 treat posture observations versus actual vulnerabilities — reachability is not the same thing as exploitability.

CategoryDrives headline?Examples
vulnerabilityYesEOL OpenSSH, expired cert, self-signed cert, cleartext HTTP
cveYes — uses the worst matched CVE's NVD CVSSNVD CVE keyword/CPE match
exposureNo — listed for postureSSH reachable on the public internet, sensitive port reachable
hardeningNo — listed for postureBanner version disclosure, shadow asset (inventory gap)

4. Per-host aggregation

Headline severity is the maximum CVSS among findings whose category is vulnerability or cve. CVSS is explicitly not aggregated by addition — adding two unrelated Mediums should not produce a High, because CVSS bands are anchored to specific real-world impacts (FIRST.org spec §5).

Two adjustments apply on top of the raw max:

  • CVE-match override — the cve finding's CVSS is replaced with the worst matched CVE's own NVD score, so a host that only matches historical low-severity CVEs no longer reports as High.
  • KEV override — any matched CVE in CISA KEV promotes the headline to at least 9.0 (Critical), reflecting CISA's BOD 22-01 remediation priority.

The 0–10 headline is also reported as a 0–100 score (headline × 10) for analyst convenience.

4. Severity bands

Reported severity follows CVSS v3.1 §5 verbatim:

BandCVSS range
None0.0
Low0.1 – 3.9
Medium4.0 – 6.9
High7.0 – 8.9
Critical9.0 – 10.0

5. Finding catalog

Findings live in dojaa/scoring/findings.py. Every finding carries: stable ID, CWE, CVSS v3.1 vector, NIST SP 800-53 controls that mitigate it, MITRE ATT&CK techniques it enables, authoritative references, and remediation guidance.

6. Reproducing a score

  1. Open a host detail page.
  2. Expand "Standards mapping & remediation" under any finding to see its CVSS vector.
  3. Paste the vector into the FIRST.org online calculator — the base score matches.
  4. For matched CVEs, the displayed CVSS score is the NVD-published value; the EPSS column is the FIRST.org probability of exploitation in the next 30 days; the KEV badge is direct membership in CISA's catalog.
